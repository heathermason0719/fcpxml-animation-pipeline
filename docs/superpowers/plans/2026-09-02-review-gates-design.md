# Storyboard、480p Demo 与原生渲染三段门禁设计

## 状态

用户已于 2026-09-02 确认本设计方向。本文先冻结目标契约；对应页面、审核记录、失效传播和渲染硬门尚未实现，因此在实现完成并通过测试前，不得把本文描述为当前可靠能力。

## 问题

现有流程虽然区分 A11 hero frame、480p 完整动画审阅和原生透明渲染，但审核交付与自动门禁没有完整对齐：

- 本轮只向用户交付了静帧候选联系表，没有交付可逐镜评论的正式 Storyboard 页面；
- 480p Demo 可以播放，但没有按时间码或时间段记录运动反馈的正式入口；
- `render_animations.py` 目前只验证 adapter 与 layout lock，没有验证 480p Demo 已批准，也没有验证用户针对原生渲染的独立授权。

因此，流程说明可能要求先审小样，但执行层仍可能跨过运动审核直接进入原生渲染。

## 已确认的三段流程

### 1. Storyboard 静态样式审核

Storyboard 是静态设计审核界面，负责排版、文字、素材选择、信息层级、比例、留白、颜色、边框和材质关系。候选联系表可以作为内部挑选或方案比较材料，但不能替代正式 Storyboard 页面。

页面必须按稳定 cue ID 逐镜展示真实文案、设计说明和静帧，并允许用户在镜头或具体静帧下填写 comment、标记“通过”或“需修改”。记录保存在当前 Vn 内，并进入结构化审核状态；聊天只用于讨论复杂问题，不作为唯一审核凭证。

每个镜头必须有 1 张主审帧。主审帧不是机械中间帧，而是主要元素已经进入并停稳、文字完整可读、原片主体自然清晰、静态设计信息最完整且不存在转场、过冲、遮挡或退场干扰的代表状态。

当一个镜头存在无法由主审帧完整表达的静态构图变化时，可以额外增加 1 或 2 张辅助帧，因此每镜总计 1 至 3 张静帧。辅助帧只解释构图状态变化，不承担运动路径展示。仅有入场路径、缓动或节奏差异时不增加辅助帧，留到 480p Demo 审核。

同组 A/B/C 样式候选必须使用相同语义状态、相同原片帧和相同真实文案，只改变待比较的设计变量，避免候选通过选择不同内容状态获得不公平优势。

只有所有相关 cue 的未解决 comment 已清空、逐镜状态均通过且 layout lock 与获批静帧一致时，静态审核才成立。任何布局依赖、文字、素材、投影规格或获批静帧变化都会使受影响 cue 重新进入静态审核。

### 2. 480p Demo 运动审核

静态审核通过后，才在独立 motion 层实现运动并生成保留粗剪原声的 854×480 Demo。该阶段只审核运动路径、节奏、缓动、停顿、转场和镜头衔接，不重新定义已冻结的静态布局。

Demo 审核页必须允许用户在当前播放时间点添加 comment，并自动记录时间码和对应 cue；持续性问题可以记录起止时间。comment 可以标注运动路径、节奏、转场、衔接或其他类别，并保存处理状态。聊天用于实时推敲解决方案，页面中的结构化记录负责最终验收与自动门禁。

只有所有运动 comment 已解决、用户明确将 Demo 标记为通过，并且审核记录绑定的 Demo 文件哈希与当前实际文件一致时，运动审核才成立。运动实现、Demo 文件或其依赖变化会使运动审核及后续原生渲染授权失效；单纯讨论或 Agent 自行判断不能代替用户批准。

### 3. 原生通道视频授权与渲染

Storyboard 静态审核通过和 480p Demo 运动审核通过，仍然不自动授权原生渲染。用户必须针对当前已批准状态再执行一次独立、明确的原生渲染授权；不得从“继续”“大方向没问题”、静帧通过或 Demo 通过中推断该授权。

授权记录必须绑定当前 A11 layout lock、当前运动依赖和已批准 Demo 的文件哈希。上述任一输入变化都使授权失效。`render_animations.py` 必须 fail closed：缺少静态批准、运动批准、有效锁或匹配的显式授权时，不得启动原生 ProRes 4444 渲染。

授权只允许进入当前输入状态的原生通道视频渲染，不自动授权覆盖已有 MOV、注册资产、构建 FCPXMLD、导入 Final Cut Pro、commit 或 push。

## 审核记录与权威边界

- `animation-manifest.json` 继续是工作流状态与渲染门禁的机器权威；页面 comment 和批准结果必须形成 Vn 内可校验的结构化记录，并由 manifest 引用或承载，不能只存在于浏览器内存、`localStorage` 或聊天历史中。
- Storyboard 页面和 Demo 审核页是生成视图，不成为第二套布局、运动或时间权威。
- FCPXML/FCPXMLD 继续独占精确时间、帧率和有理数时间基准；页面时间码只用于定位审核意见。
- comment 修改、解决和批准写入必须经过受控本地接口校验，静态 HTML 不得任意改写 Vn 文件。
- 自动检查负责可打开性、资源、哈希、状态和门禁一致性；审美与运动是否通过始终由用户决定。

## 失效传播

```text
布局/文字/素材变化
  -> 受影响 cue 的 Storyboard 批准失效
  -> 其 layout lock 失效
  -> 480p Demo 批准失效
  -> 原生渲染授权失效

仅运动或 Demo 变化
  -> Storyboard 批准保持有效
  -> 480p Demo 批准失效
  -> 原生渲染授权失效

审核状态未变且输入哈希一致
  -> 用户仍需单独授权
  -> 才可启动原生渲染
```
