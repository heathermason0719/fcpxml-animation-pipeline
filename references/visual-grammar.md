# 动画视觉语法路由

## 用途

本参考是当前 work model 中按需使用的创作判断辅助，不是逐镜必填清单或审核流程，也不规定字体、颜色、材质和动画参数。先理解整集论证，再判断哪些段落需要动画；无需为没有动画的段落填写路由。

需要比较具体表达方案时，可以依次考虑：

1. **功能**：这条动画首先要解决什么信息问题；
2. **与原画的关系**：包装应当建立独立信息层，还是服从原电影画面的既有构图；
3. **可参考的视觉语言**：为了完成前两项，可以借鉴哪一种表达体系；
4. 在已确认的项目级 `frame.md` 与统一运动气质范围内形成具体方案。

后一步不能反向替代前一步。不得因为熟悉某种组件、风格或效果，就先选择形式，再为它寻找用途。

## 1. 功能索引

先确定一个主功能；确有需要时可以记录次要功能，但具体设计必须优先服务主功能，不能把多个次要目标堆叠为失去重点的方案。

当前索引包括：

- 强调一句旁白；
- 标人物身份；
- 标镜头信息；
- 补充解释；
- 对比两个概念；
- 指向画面局部；
- 展示步骤或数据；
- 段落标题。

该索引开放。可以用更准确的词描述信息任务；值得保留的取舍写入 cue 的说明或可选 designRoute，不为匹配枚举而错误归类。

## 2. 与原画的关系

### A：包装主导（overlay-led）

原电影画面主要作为内容和氛围底图，包装可以建立较强的独立版式与信息层级，并在合理范围内改变原画面的视觉重心。

### B：原画主导（source-led）

原电影画面已经形成完整构图，包装只在必要位置介入，必须服从人物、视线、动作、景别、留白和原有视觉重心。

采用此分析时，明确原画与包装的主次关系。允许局部或短暂的辅助关系，但不以“混合”回避构图判断；有用的理由随 cue 保存。

“照顾、避让、保留原画可见性”本身不构成 B；只有当原画承担不可替代的信息或叙事功能时，才计入 B。混合态应通过双删除测试确认，避免所有设计都被归成主辅混合：分别假设删除包装和删除原画，只有两层各自都承担不可由另一层替代的信息或叙事功能时，才使用 A/B 混合关系。

## 3. 可参考的视觉语言

视觉语言是寻找解法的参照系，不是默认需要出现的元素，也不是渲染组件名。只能在功能和原画关系明确后选择。

项目级 `frame.md` 和视频级运动气质为未特别说明的 cue 提供默认风格。用户脚本若对某一镜明确指定视觉或运动风格，该逐镜要求在其明确范围内优先于项目级通用风格；没有明确指定的属性仍回落到项目默认。逐镜要求不得改变 FCPXML 时间权威、AfterForge 产品范围、读写边界、交付协议或后端能力边界。覆盖范围不清且会改变创作含义或可靠实施时，先提出一个聚焦问题，保留原话与所指 cue，不自行扩大解释。

当前索引包括：

- 信息卡片；
- 电视节目包装；
- 动态海报；
- UI / HUD；
- 杂志排版；
- 电影字幕；
- 编辑批注；
- 导演笔记；
- PPT 式解释图；
- 视觉注释。

该索引同样开放。可以选择一个主要参考语言和必要的辅助语言，也可以在现有词汇不足时增加新语言；每次选择都必须服务已确定的功能和原画关系，不能因为视觉语言自身醒目或易于实现而采用。

## 4. 自主判断与用户审阅

- 根据当前问题选用分析方法，普通技术实现由 Agent 判断；本路由参考不额外新增路由表、逐镜确认或静态批准门，也不改变工作模型已有的首次设计确认条件。
- 方案、产物和反馈使用稳定的段落/Cue ID。用户提供镜号时保留原镜号；反馈也可指向整集、多个 Cue 或时间范围。
- 逐镜风格要求在明确范围内优先，保存来源与取舍。原话和处理过程属于 feedback，最终动画说明只描述当前结果。
- 静帧和动态小样来自同一 canonical composition/motion。冷启动对象在首次确认前只能依据明确、范围受限的 Motion 探索试做动态；否则先以静态 Storyboard 建立首次设计确认。根据实际影响更新相应小样，不要求用户选择 static/motion 或办理阶段回退。
- 首次确认后的创作对象保持 active；字体、构图、摆放、运动和完整重做都可直接推进。局部创作可自由修改和试做；只有对象、范围、跨版本连续性或授权有实质歧义时才聚焦澄清，不能把本参考当成新的回退或批准门。
- 通过 afterforge.py update 发布修改，preview 生成相关局部或完整小样。Review 从 manifest 展示当前方案与产物，不另外维护 storyboard 权威。
- 明确的创意歧义在实施受影响部分前澄清，其余内容继续。机器校验不代替用户审美判断；可查看的讨论结果及时提交，临时 QA 限制不自行升级为交付故障。
- 正式交付绑定当前完整审阅集合的用户批准与制作授权，支持明确的合并指令。讨论稿、局部认可与静态认可不能替代完整审阅授权。

## 5. 各资产边界

- 本文件只提供跨项目的可选分析方法。
- 系列视觉默认保存在 `AfterForge/工程/frame.md`；制作版使用自己的 `frame.md` 快照。规范只负责视觉与运动默认，不定义工作流程或批准条件。
- 本集理解与论证段落保存在 manifest 的 brief；Cue 保存当前表达及可选 designRoute。无需把本索引复制到每个项目。
- Review 和按需脚本导出读取同一份 manifest 内容；canonical compositions 实现当前表达方案。
- schema 2.0 的旧 storyboard 与阶段语义仅按 legacy 合同解释。
