# 动画视觉语法与概念图设计

## 用途

本参考支持当前 work model 的表达判断与概念图制作。第 1–3 节是按需选用的分析方法；生成、修改或比较概念图时使用第 4 节。它不是逐镜必填清单或新增审核流程，不规定通用字体、颜色、材质和动画参数。先理解整集论证，再判断哪些段落需要动画；无需为没有动画的段落填写路由。

需要比较具体表达方案时，可以依次考虑：

1. **功能**：这条动画首先要解决什么信息问题；
2. **与原画的关系**：包装应当建立独立信息层，还是服从原电影画面的既有构图；
3. **可参考的视觉语言**：为了完成前两项，可以借鉴哪一种表达体系；
4. 结合当前制作版明确采用的视觉默认与运动要求形成具体方案；新工作不自动沿用历史系列审美。

后一步不能反向替代前一步。不得因为熟悉某种组件、风格或效果，就先选择形式，再为它寻找用途。

## 1. 功能索引

先确定一个主功能；确有需要时可以记录次要功能，但具体设计必须优先服务主功能，不能把多个次要目标堆叠为失去重点的方案。

当前索引包括：

- 强调一句旁白；
- 标人物身份；
- 标镜头信息；
- 补充解释；
- 对比两个概念；
- 指向画面局部；
- 展示步骤或数据；
- 段落标题。

该索引开放。可以用更准确的词描述信息任务；值得保留的取舍写入 cue 的说明或可选 designRoute，不为匹配枚举而错误归类。

## 2. 与原画的关系

### A：包装主导（overlay-led）

原电影画面主要作为内容和氛围底图，包装可以建立较强的独立版式与信息层级，并在合理范围内改变原画面的视觉重心。

### B：原画主导（source-led）

原电影画面已经形成完整构图，包装只在必要位置介入，必须服从人物、视线、动作、景别、留白和原有视觉重心。

采用此分析时，明确原画与包装的主次关系。允许局部或短暂的辅助关系，但不以“混合”回避构图判断；有用的理由随 cue 保存。

“照顾、避让、保留原画可见性”本身不构成 B；只有当原画承担不可替代的信息或叙事功能时，才计入 B。混合态应通过双删除测试确认，避免所有设计都被归成主辅混合：分别假设删除包装和删除原画，只有两层各自都承担不可由另一层替代的信息或叙事功能时，才使用 A/B 混合关系。

## 3. 可参考的视觉语言

视觉语言是寻找解法的参照系，不是默认需要出现的元素，也不是渲染组件名。只能在功能和原画关系明确后选择。

当前制作版明确采用的 `frame.md` 和视频级运动要求为未特别说明的 cue 提供默认风格。用户脚本若对某一镜明确指定视觉或运动风格，该逐镜要求在其明确范围内优先；没有明确指定的属性才回落到已采用的默认。新工作不因存在系列规范就自动继承其审美。逐镜要求不得改变 FCPXML 时间权威、AfterForge 产品范围、读写边界、交付协议或后端能力边界。覆盖范围不清且会改变创作含义或可靠实施时，先提出一个聚焦问题，保留原话与所指 cue，不自行扩大解释。

当前索引包括：

- 信息卡片；
- 电视节目包装；
- 动态海报；
- UI / HUD；
- 杂志排版；
- 电影字幕；
- 编辑批注；
- 导演笔记；
- PPT 式解释图；
- 视觉注释。

该索引同样开放。可以选择一个主要参考语言和必要的辅助语言，也可以在现有词汇不足时增加新语言；每次选择都必须服务已确定的功能和原画关系，不能因为视觉语言自身醒目或易于实现而采用。

## 4. 概念图：传递任务、看图、迭代

### 给图像模型的是创作任务

用简洁自然语言交代与这次设计有关的上下文：观众要理解什么，原片与新增设计各承担什么，准确文案、画幅、出现顺序，以及本图代表的一个时刻。需要多状态比较时明确区分各状态，避免把先后时刻误画成同屏重复。无需把完整流程、合同或实现参数塞进提示词。

把内容、原片保留范围、字幕空间等实际约束与可发挥的审美分开。明确的用户要求和本版已采用规范继续有效；未定的字形、比例、色彩、层级与组合方式可交给模型探索。具体表达方向比“优雅、精致”更能组织画面，但应服务内容，不建立固定风格菜单。提示词短不等于失去上下文，写满字号、坐标和禁用效果也不等于设计完整。看过结果后，可以为明确的问题作具体设计决定。

对每张输入图说明用途：原片是构图依据或编辑目标，方位草图只约束空间关系，风格参考只提供指定的字形、层级或气质。只参照方位不等于复制图标；静态海报参考不等于把整张海报的布局、文案或装饰搬进视频。某条俯视图的简化要求不扩展为全片文字风格。

例如，可这样交代一个文字叠层任务，按实际材料替换，而非固定照抄：

> 这是电影解说中的一个镜头，原片会继续播放，人物与场景仍承担叙事。请设计“限制”“选择”“代价”三组文字，随旁白依次出现；这张只展示三组全部出现的时刻。希望有电影宣传页的设计感，请发挥字形与排版，让单项和整体都成立。保留所指人物与原有标题，底部留给字幕，只使用这三个词。

独立画面或包装主导的任务应按其实际需要安排主次，不机械要求所有设计缩小、靠边或服从原片。

### Agent 完成看图与多轮修改

每次检查实际图像：内容是否准确，主次和阅读路径是否清楚，视觉气质是否符合当前任务，是否有遮挡或擅加内容。合理判断哪些元素能独立制作、分次出现与停留，部分元素出现时构图是否仍成立。可制作性依据元素和时间关系判断，不因熟悉 HTML 的简单画法而提前削弱设计；静态概念不能证明实际动效、节奏或重建保真度。

方向有效时，保留有效部分，下一次生成聚焦于已观察到的问题，如字重复、文字压住主体、比例失衡或三组语言不统一。整体气质被否定时，回到原始素材和当前意图重起，只带入仍有效的约束与已认可特征，避免持续引用被否定的候选图；这不宣称工具内部记忆已被清空。调用时只把实际包含的参考图说成已提供。

Agent 自主完成必要的生成、筛选和修改，不要求用户逐张指出可识别的问题或逐次批准重新生成。解决已知需求与明显问题后，交付值得讨论的候选；真正未定的审美交给用户选择，不用无止境精修替代审阅。没有固定重试次数，也不强制每次先出多版。保留实际提示词与输入图对应关系，用户询问时提供原稿，不用事后改写的提示词冒充实际调用。

### 多方向比较

用户要求多方向，或确实存在值得比较的表达分歧时，再组织候选。各版使用可比较的内容、原片时刻与呈现状态，并满足同一任务要求；每版都应有成立的表达立场、视觉语言或组织方式。仅换颜色、故意做弱稿或把不适用于视频的漂亮图片拿来凑数，不构成有效比较。说明区别及运动意图；若方向涉及不同内容或剪辑，先按任务范围处理，不能以风格探索暗中改写。

概念按现有接口登记为候选，推荐不等于采用；选择仍由用户明确表达。具体登记、确认和保存规则见 `SKILL.md`，本节不增加表单、阶段、批准门或机器审美评分。一次认可或否定只在相应作品和属性范围内生效，不自动成为以后必须用宋体、极简或禁止某类效果的通则。

## 5. 自主判断与用户审阅

- 根据当前问题选用分析方法，普通技术实现由 Agent 判断；本路由参考不额外新增路由表、逐镜确认或静态批准门，也不改变工作模型已有的首次设计确认条件。
- 方案、产物和反馈使用稳定的段落/Cue ID。用户提供镜号时保留原镜号；反馈也可指向整集、多个 Cue 或时间范围。
- 逐镜风格要求在明确范围内优先，保存来源与取舍。原话和处理过程属于 feedback，最终动画说明只描述当前结果。
- fresh work model 2.2 在代码制作前先有真实概念图并由用户明确采用；图片候选可自由迭代。确认后，实际 Storyboard 和动态小样来自同一 canonical composition/motion，Storyboard 检查制作结果，不重复首次设计确认。历史 2.1 的确认前 Motion 探索只按原合同解释。根据实际影响更新小样，不要求用户选择 static/motion 或办理阶段回退。
- 首次确认后的创作对象保持 active；字体、构图、摆放、运动和完整重做都可直接推进。局部创作可自由修改和试做；只有对象、范围、跨版本连续性或授权有实质歧义时才聚焦澄清，不能把本参考当成新的回退或批准门。
- 通过 afterforge.py update 发布修改，preview 生成相关局部或完整小样。Review 从 manifest 展示当前方案与产物，不另外维护 storyboard 权威。
- 明确的创意歧义在实施受影响部分前澄清，其余内容继续。机器校验不代替用户审美判断；可查看的讨论结果及时提交，临时 QA 限制不自行升级为交付故障。
- 正式交付绑定当前完整审阅集合的用户批准与制作授权，支持明确的合并指令。讨论稿、局部认可与静态认可不能替代完整审阅授权。

## 6. 各资产边界

- 本文件提供跨项目的表达分析与概念图制作方法，不保存单个项目的审美偏好或生产事实。
- 系列视觉默认保存在 `AfterForge/工程/frame.md`；制作版使用自己的 `frame.md` 快照。规范只负责视觉与运动默认，不定义工作流程或批准条件。
- 本集理解与论证段落保存在 manifest 的 brief；Cue 保存当前表达及可选 designRoute。无需把本索引复制到每个项目。
- Review 和按需脚本导出读取同一份 manifest 内容；canonical compositions 实现当前表达方案。
- schema 2.0 的旧 storyboard 与阶段语义仅按 legacy 合同解释。
