# 动画视觉语法路由

## 用途

本参考用于具体动画形成方案之前的创作判断。它不是可直接套用的设计规范、风格预设或组件清单，也不规定字体、颜色、材质和动画参数。

每条候选动画必须按以下顺序判断：

1. **功能**：这条动画首先要解决什么信息问题；
2. **与原画的关系**：包装应当建立独立信息层，还是服从原电影画面的既有构图；
3. **可参考的视觉语言**：为了完成前两项，可以借鉴哪一种表达体系；
4. 在已确认的项目级 `frame.md` 与统一运动气质范围内形成具体方案。

后一步不能反向替代前一步。不得因为熟悉某种组件、风格或效果，就先选择形式，再为它寻找用途。

## 1. 功能索引

先确定一个主功能；确有需要时可以记录次要功能，但具体设计必须优先服务主功能，不能把多个次要目标堆叠为失去重点的方案。

当前索引包括：

- 强调一句旁白；
- 标人物身份；
- 标镜头信息；
- 补充解释；
- 对比两个概念；
- 指向画面局部；
- 展示步骤或数据；
- 段落标题。

该索引开放。Agent 可以在现有词汇不足以准确描述信息任务时增加新功能，但必须在 manifest 中用简短理由说明，不能为了匹配既有枚举而错误归类。

## 2. 与原画的关系

### A：包装主导（overlay-led）

原电影画面主要作为内容和氛围底图，包装可以建立较强的独立版式与信息层级，并在合理范围内改变原画面的视觉重心。

### B：原画主导（source-led）

原电影画面已经形成完整构图，包装只在必要位置介入，必须服从人物、视线、动作、景别、留白和原有视觉重心。

每条动画必须确定一个主关系。允许以另一关系作为局部或短暂的辅助关系，但不能用“混合”回避构图判断；manifest 必须记录主关系及采用混合关系的理由。

“照顾、避让、保留原画可见性”本身不构成 B；只有当原画承担不可替代的信息或叙事功能时，才计入 B。混合态应通过双删除测试确认，避免所有设计都被归成主辅混合：分别假设删除包装和删除原画，只有两层各自都承担不可由另一层替代的信息或叙事功能时，才使用 A/B 混合关系。

## 3. 可参考的视觉语言

视觉语言是寻找解法的参照系，不是默认需要出现的元素，也不是渲染组件名。只能在功能和原画关系明确后选择。

当前索引包括：

- 信息卡片；
- 电视节目包装；
- 动态海报；
- UI / HUD；
- 杂志排版；
- 电影字幕；
- 编辑批注；
- 导演笔记；
- PPT 式解释图；
- 视觉注释。

该索引同样开放。可以选择一个主要参考语言和必要的辅助语言，也可以在现有词汇不足时增加新语言；每次选择都必须服务已确定的功能和原画关系，不能因为视觉语言自身醒目或易于实现而采用。

## 4. 自主判断与用户验收

- Agent 默认自主完成逐条视觉语法路由，不新增逐条用户确认；
- 路由清单、manifest 和 storyboard 必须使用一致的稳定 cue ID，并在用户材料提供镜号时同时保留原镜号，避免反馈只能依赖列表顺序；
- 路由结果写入草稿 `animation-manifest.json`，并在既有 A11 storyboard 联合验收中与真实文案、具体方案和静态关键画面一起暴露；
- 用户反馈先修正草稿 manifest，再重新生成 storyboard 和受影响的关键画面；
- 只有判断分叉会显著改变任务范围、违反已确认约束或产生难以逆转的后果时，才在 A11 之外单独请求确认；
- 普通设计分歧、可低成本返工的判断和具体表现选择由 Agent 负责。

## 5. 各资产边界

- 本文件是跨项目的 Skill 判断参考；
- 项目级 canonical `AfterForge/frame.md` 只保存该视频已经确认的整体视觉包装规范，不复制本索引；
- 每条动画实际采用的功能、原画关系、参考语言和理由保存在 `animation-manifest.json` 的 cue 级 `designRoute` 中；
- `STORYBOARD.md` 只展示草稿 manifest 中的路由与具体方案供用户验收，不成为第二权威源；
- HyperFrames compositions 只实现已经确认的方案，不从成品反推或改写上游判断。
